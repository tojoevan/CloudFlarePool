## 1. 目的

集中承载"测试类"工程资产：测试策略与分层、测试工具与运行方式、测试用例清单、测试执行记录。让测试方案、用例、结论有统一入口，避免散落在代码注释与对话中，也为后续 CI / 回归提供基线。

## 2. 范围

覆盖平台核心（数据湖、网关）与前端小程序的测试资产。不包含安全合规审计清单（见 `04-检视.md` §2）与发布节奏（见 `05-开发指南.md` §5）。

## 3. 测试策略与分层

- **分层**
  - **集成 / smoke（数据湖）**：真实 D1 + R2 内存绑定，验证 CRUD、用户级隔离、租户隔离、鉴权守卫端到端。
  - **单元 / 契约（网关）**：mock 数据湖 + mock 微信，验证登录签发、反代头注入、token 校验、不透传客户端令牌。
  - **前端 handler 验证（小程序）**：node mock 微信运行时实跑 handler 断言（历史采用，建议沉淀为可回归测试）。
- **工具栈**：`node:test`（原生测试运行器）、`miniflare`（本地 Workers 运行时 + D1/R2 内存绑定）、`esbuild`（打包 Worker 为可被 Miniflare 加载的 bundle）。无外部测试框架依赖。
- **密钥**：测试用 Ed25519 密钥对在测试内 `generateKeyPairSync` 即时生成，公钥注入 `JWT_PUBLIC_KEYS` 绑定，不依赖生产密钥。

## 4. 测试环境与运行命令

| 模块 | 命令 | 说明 |
|------|------|------|
| 数据湖 | `npm run bundle:test` 后 `node test/smoke.test.js` | esbuild 打包 `src/index.js` → `dist/test-bundle.mjs`，Miniflare 加载该 bundle + D1/R2 绑定；测试结束须 `mf.dispose()` + `process.exit(0)`，否则 workerd 子进程挂起导致进程不退出 |
| 网关 | `cd gateway && npm test` | `node --test test/jwt.test.mjs test/gateway.test.mjs`（脚本已修复 `node --test test/` 目录误用为单文件的问题） |
| 前端小程序 | （历史）node mock 微信运行时实跑 handler | 建议在 `jiashiben/` 沉淀为可复跑测试，纳入本档 §5.3 |

### 5.4 前端发布门禁与静态校验（2026-08-15 建立）
**背景**：本次编辑页 bug——编辑页底部 `.action-bar` 与 `app.wxss` 全局同名类（列表页"搜索+新建"胶囊条，带 `transform:translateX(-50%);width:666rpx`）冲突，CSS 按属性逐条判胜负，页面重写 `left/right/bottom` 却漏 `transform/width`，导致底栏左移 333rpx、删除按钮被裁出屏幕。后端每次改动有 `npm test`（12/12）把门，前端此前**无任何回归门禁**，致使"有问题版本"被编译进真机预览。用户确立原则：**不应发布有问题版本**。

**① WXSS 同名类冲突静态 lint（已落地）**
- 脚本：`jiashiben/scripts/lint-wxss-conflicts.mjs`（纯 Node 内置模块，无依赖）
- 原理：提取 `app.wxss` 全量类名 → 与各页面 `.wxss` 定义类名求交集；对"全局类自身带 `position:fixed / transform / left / right / top / bottom`"的同名项标 **⚠️ 高危（布局泄漏风险）**，其余标 `· 同名（可能为设计系统复用）`。
- 运行：
  ```bash
  node scripts/lint-wxss-conflicts.mjs            # 报告所有同名，高危标 ⚠️
  node scripts/lint-wxss-conflicts.mjs --strict   # 存在高危同名则退出码 1（挂发布）
  ```
- 解读：`.action-bar` / `.tabbar` / `.fab-press` 等全局布局类若被页面**重定义**即为真冲突（如本次），必须改名或显式覆盖全部定位属性；`.btn-primary` / `.card` / `.active` 等设计基础类页面复用属正常，仅作 [info] 提示、不阻断。
- 实测（修复后）：扫描 6 个页面文件，同名 20 处、**高危 0 处**（编辑页已改名为 `.edit-actions`，不再冲突）。

**② 前端发布门禁清单（对齐后端 test 纪律）**
上传新版本小程序前，逐项确认：
1. 开发者工具「编译」（Cmd/Ctrl+B）重新构建，且无报错；
2. 跑 `node scripts/lint-wxss-conflicts.mjs --strict` → 高危 0；
3. 核心页冒烟（编译后真机/模拟器目检）：编辑页（删除+保存按钮完整、不偏出边界）、列表页（搜索+新建胶囊居中）、详情页关键按钮可见；
4. **已知 broken 状态禁止上传**（如本编辑页 bug 在修复前即属 broken，不应发布）。

**③ 已知 broken 固化原则**：任何"已发现但未修复"的前端缺陷，在修复并重新验证前，不得上传新版本；缺陷与修复均记入本档 §6 与 `03-待办.md`。

> 上述门禁为「发布流程」的前端子项；端到端编排与 Gate 判定见 `05-开发指南.md` §6。
