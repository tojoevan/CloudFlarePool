## 三、平台健壮性短板（hardening / 运维，未处理）

- **R2 图片无生命周期**：删除待办 / 档案时不删 R2 对象 → 孤儿文件随时间累积（`data.js` 删除路径无 R2 调用）。
- **网关安全头缺失 + 错误泄露**：`server.js` 仅设 content-type，无 CORS / CSP / HSTS；对客户端回传 `detail:e.message`（`server.js:226,413`），可能泄露内部细节。
- **一键部署按钮 / 路由是"活的"**：管理后台 `app.js:22,566,661+` 仍带部署按钮并轮询 `/api/t4data/deploy`，后端路由也在。**非 Canvas A 残留**（修正此前说法）——原生产后台就一直有；若服务器缺 `deploy.sh` 则触发失败。属悬空能力 / 配置错位。
- **无 CI、无监控告警、无自动备份**：数据湖有集成测试但无 `.github` 流水线；`scripts/backup.sh`、`scripts/monitor.sh` 均手动；无 incident runbook。
- **账号（users）无自助注册 / 改密 / 重置**：`account.js` 仅 `/verify`，账号只能 DB 直写（管理员自助改密已实装，`admin.js:150`）。
- **令牌无吊销机制**：Ed25519 JWT 仅验 `exp`，泄露只能等过期。

## 四、架构清晰度

- `jiashiben/backend/` 是**第二套并行后端**（自有 HMAC 鉴权、`todos` 表无 `tenant_id`、`family_id IN` 共享查询），与数据湖职责重叠、权威不明。文档定位为可选本地 relay（`CLOUD_ENABLED=false` 默认），但双后端易引发混乱，建议在文档中明确边界或择期合并。
