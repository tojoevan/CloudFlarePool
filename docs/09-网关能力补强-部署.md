# 网关能力补强 · 部署与验证

> 对应需求：① 便捷授权（agent 快速查询/编辑）② 普通用户密码重置 ③ T3 服务密钥说明与备注
> 改动范围：数据湖（D）、网关（C）、管理后台 SPA（C）。

## 一、改了什么（速览）

### ① 便捷授权：打通 T3 M2M 通道 + 后台代签
- **根因**：数据湖早已完整支持 T3 服务令牌（`verifyServiceToken` + `dualGuard` 已识别 `typ=service` 并按 `scope` 鉴权），但**网关此前只接了 `/api/data/`、`/api/t2data/`、`/api/t4data/` 三个通道，没有 `/api/t3data/`**，导致服务密钥"签了也用不了"。
- 网关新增 `gateway/lib/keyring.js`：持有服务密钥 `raw_secret` 的本地密钥环（内存 + 文件持久化，权限 0600）。
- 网关新增 `POST /api/t4data/tokens/mint`（T4 管理员）：确保目标租户存在可用服务密钥（无则经 X-Sync-Key 在数据湖建一个并捕获 `raw_secret`），用 `signServiceToken` 代签一个**短期 T3 Bearer** 返回，agent 直接粘贴即可。
- 网关新增 `GET/POST/... /api/t3data/*` 通道：仅放行 `typ=service`，本地验签 + `scope` 校验后按令牌 `tid` 路由到 `数据湖 /t/:tenant/*`；原样转发 T3 Bearer，数据湖再次验签（纵深防御）。
- 签发服务密钥（`POST /api/t4data/keys`）时，网关把 `raw_secret` 捕获进密钥环，便于后续代签。

### ② 普通用户密码重置
- 数据湖新增 `POST /admin/users/:id/reset`（T4 管理员、租户内、复用 `hashPassword` + 审计）。
- 管理后台「用户账号」表新增**重置密码**按钮（同现有管理员重置交互）。

### ③ T3 服务密钥说明与备注
- `api_keys` 表新增 `label / note / used_by / expires_at` 四列（迁移脚本见下）。
- 数据湖 `keys.js`、`admin.js` 的密钥路由读写这些字段；新增 `POST /admin/keys/:id/meta` 供后台编辑备注。
- 后台「服务密钥」页：加用途说明、备注/使用者/有效期列、可编辑备注，以及「签出访问令牌」面板。

## 二、部署顺序（重要）

```bash
# 0) 本地先自测（已在仓库外 /tmp/test_gw.mjs 通过 13 项，含 crypto 往返与通道守卫）
#    生产部署步骤如下：

# 1) 数据湖 D1 加列（一次性，已有列会报已存在，可忽略）
wrangler d1 execute cloudflarepool --remote --file=scripts/migrate-keys-meta.sql

# 2) 部署数据湖（新增 /admin/users/:id/reset、/admin/keys/:id/meta、密钥 meta 读写）
#    （按既有流程：git push 后 wrangler deploy，或用服务器一键部署）
wrangler deploy

# 3) 部署网关（新增 /api/t3data/*、/api/t4data/tokens/mint、密钥环）
#    - scp 网关目录到服务器（注意 .env / keyring.json 不入库、不覆盖既有 keyring）
#    - 在服务器 .env 增加 KEYRING_FILE 与 MINT_TENANTS（见 .env.example）
#    - 首次将 KEYRING_FILE 指向受保护路径并 chmod 600：
#        echo "KEYRING_FILE=/opt/gateway-keyring.json" >> /path/to/gateway/.env
#        touch /opt/gateway-keyring.json && chmod 600 /opt/gateway-keyring.json
#    - 重启网关（pm2 restart home-inkspcl 或对应命令）

# 4) 同步管理后台 SPA（deploy 脚本会把 gateway/public/admin 同步到站点根）
#    （如果走服务器一键部署，此步随网关发布一并完成）
```

> 顺序建议：先 **1 迁移** → **2 数据湖** → **3 网关** → **4 SPA**。
> 即使漏跑迁移，数据湖代码对缺失列有容错（仅后台不显示备注），不会阻断。

## 三、验证清单

- [ ] 后台登录 → 服务密钥页出现「用途说明」与「签出访问令牌」面板。
- [ ] 在服务密钥页「签出访问令牌」：选租户=weijiashi、权限=读写、填备注 → 得到 Bearer。
- [ ] 用该 Bearer 调 `GET /api/t3data/c/weijiashi/todos`（或 cloudlet） → 200 返回数据。
- [ ] 同一令牌若选「只读」再签，对 `POST /api/t3data/...` 应返回 403。
- [ ] 用户账号页对某用户点「重置密码」→ 输入新密码 → 提示成功；该用户可用新密码登录。
- [ ] 服务密钥页点某密钥「备注」→ 填 label/使用者/备注/有效期 → 保存后列表显示。

## 四、安全与运维注意

- **密钥环文件等同私钥**：含 T3 服务密钥 `raw_secret`，可代签令牌。必须 `chmod 600`、落盘在仓库外（如 `/opt/gateway-keyring.json`），且**绝不入库**（`.gitignore` 已忽略 `keyring.json`）。
- **MINT_TENANTS 白名单**：仅列出的租户可被代签；默认 `weijiashi,cloudlet`。不要随意加租户。
- 代签令牌默认有效期 1 天（可调），按需缩短；泄露等同于该密钥权限，及时在后台吊销对应密钥（`/admin/keys/:id/revoke`）。
- 网关重启后密钥环从文件重载；若文件丢失，代签会重新在数据湖建新密钥（旧密钥仍可在后台吊销）。
