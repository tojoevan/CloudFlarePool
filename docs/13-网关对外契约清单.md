# 13 · 网关对外契约清单（G2 · 契约盘点）

> 建立：2026-09-06 ｜ 性质：**事实清单**（穷举自代码，非设计）
> 作用：① G1 语义路由映射表的**唯一输入**；② 此后新增对外路径必须登记，未登记不得上线

> 原则：**只盘不改**——本文产出不改动任何运行时行为。

## 一、定义与判据

**契约 = 业务端（客户端）实际依赖的网关路径集合。**

- 判据：某个路径被客户端代码硬编码调用，且**改动它会迫使客户端发版**，它就是契约。
- 反例：网关自有端点（登录、deploy、health）由网关自行演进，客户端虽调用但不映射数据湖，不进映射表。
- **L1 屏蔽的实质**：契约里不应出现任何数据湖路径形状（`/t/{tenant}/...`、`/admin/...`）。当前**全部违反**，见 §三。

**已实现行为（与 `gateway/server.js` 一致，勿按旧稿理解）**

| 情况 | 行为 |
|---|---|
| 表缺失 / 损坏 | `/api/v1/*` 整体 **503**，旧通道完全不受影响（fail-closed for v1，绝不静默透传） |
| 表存在但未命中 | **404**（未登记的契约） |
| 命中但方法不在契约内 | **404** |
| 命中且方法匹配、无令牌 | **401**（证明表已加载且路由命中） |

**设计要点（实施 G1 时必须遵守）**
1. `match` 只声明**对外语义路径**，`to` 只声明**内部数据湖路径**，二者解耦；
2. `{tenant}` 由令牌解析注入，业务端永不传 tenant；
3. 表**外置**为 `gateway/routes.json`，改映射**不重启**；
4. **映射表按 mtime 热加载**：改映射**免重启**（网关重启需宝塔，成本高——这是外置的核心收益）；
5. 表异常时 **fail-closed for v1**（503）而非回落到透传，避免"配置写错把请求乱转发"，且旧通道不受影响；
5. 首期**只上小程序 + SPA**（共用一套 `/api/v1`），T4 通道不动。

## 六、维护说明

- 新增对外路径 → **先登记本清单**，再实现；未登记路径不得上线。
- 数据湖路径变更 → 只需改 §五 映射表，业务端零改动（这正是本清单存在的意义）。
